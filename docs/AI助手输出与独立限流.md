# AI 助手输出与独立限流

输出预算默认 5000 tokens，管理员在「AI 桌宠设置 → DeepSeek 设置 → AI 输出上限」调整，范围 500～10000；保存后生效。旧配置及旧预设缺省为 5000。普通访客接口不公开 API Key、人设、模型地址或输出预算。

每位访客最多 20 次/任意连续 60 秒、60 次/任意连续 600 秒。第 21/61 次触发 5 分钟休息，直接返回「我有点累了，需要休息一会儿。请5分钟后再来找我吧。」与倒计时，不请求 DeepSeek。休息内的重复请求不会延长休息；期满仍检查滚动窗口，不清空尚未过期的记录。

计数键是服务器签名的随机访客 Cookie，使用 HttpOnly、SameSite=Lax、正式域名 Secure，Cookie 有效期 30 天。SQLite 保存签名密钥、请求时间与休息期限，刷新、更换昵称、服务重启不会重置。两个独立浏览器访客共用 IP 时分别计数，甲休息不影响乙。同一浏览器的多个标签属于同一访客。本站昵称并非可验证账号，匿名会话不能识别清除 Cookie 后的新会话或跨设备的同一个人；此实现没有按共享 IP 合并额度。

每个会话同时只允许一个生成请求，重复并发只返回本地等待提示。现有全站 3 个生成并发槽保留，用于服务容量保护，不产生其他访客的休息或共享配额。计数采用 SQLite 事务，重试前再检查休息状态。

上游请求使用 JSON 模式及完整对象示例，检查 finish_reason、正文类型和 JSON 结构；截断、空回复、格式异常及生成中断最多重试一次，要求缩短正文。认证、余额、上游限流、连接错误及内容过滤不自动重试。总时间预算 55 秒，客户端等待 65 秒；每次上游连接最多 45 秒，读取最多 1 MB。日志仅记录分类、HTTP 状态和尝试次数，不记录问题、回复、推理过程或密钥。不会把 reasoning_content 当作回答。

完整回复保留在聊天界面，移除原有 2000 字截断；长文本约 120 次渐进显示。发送给模型的上下文最多 12 条、18000 字，单条历史助手回复最多 6000 字，用户消息最多 2000 字；上下文裁剪不删除界面的完整回复。

排查依据：旧代码固定 max_tokens=500，且将多种解析失败统一显示为「内容不完整」。没有该次请求的原始分类日志，无法确定截图中的唯一原因。DeepSeek 官方说明 JSON 模式偶尔会返回空内容，并要求足够输出预算及 JSON 示例；GitHub 也有 stop 但 content 为空的报告，属于相似现象参考。
