# 空回复与角色人设修复

2026-10-02，正式日志确认两轮 `empty attempt=1`、`empty attempt=2`；输出预算为5000，当前墨灵配置仍保存旧初音默认人设。之前补试仍使用JSON模式，可能重复遇到同一空内容问题。DeepSeek [官方JSON说明](https://api-docs.deepseek.com/guides/json_mode/)明确提示该模式可能返回空内容；日志无法说明模型内部为何产生空正文。

首次调用继续使用JSON模式取得正文/动作/表情。空正文、截断或格式异常时，唯一一次补试改用普通正文模式，并移除JSON格式要求。有效普通正文由服务器包装为聊天对象，表情normal、动作idle；完整JSON包装仍可兼容。两种模式都继续检查完成状态、正文长度、密钥脱敏，不读取推理内容或展示残缺JSON。两次都空仍显示真实错误，不伪造回答、不无限重试。默认5000/最高10000输出预算、55秒时间预算和20/60独立访客配额沿用；超限拒绝及重试前休息检查保留。

墨灵默认人设改为网站原创青玉墨精灵，不再自称初音或引用Crypton。每个可选角色都有对应默认人设。服务端读旧配置/预设时，仅将完全未改动的旧初音默认人设按当前角色替换；用户写过的自定义人设保留。原数据库字节不强制覆盖，后台重新保存后自然持久化正确人设。

后台System Prompt编辑框至少260像素高、12行、支持纵向拖动放大，深色主题保持可读。默认人设随角色切换，自定义内容不自动替换；「恢复当前角色默认人设」可恢复当前选定角色，点击保存应用。

验证包含强制JSON空回复后普通正文成功、两个模式都空仍失败且最多两次调用、不显示推理/残缺JSON、合法代码正文、默认迁移/自定义保留、此前配额与上下文回归；浏览器验证对话恢复、人设大框、两种主题、角色切换、恢复默认、保存刷新。正式部署后另外使用网站正常聊天验证数字及符号问题。

2026-10-03 v3.2.0：仅内置墨灵；完整默认人设、中文语态、名称与形象统一为墨灵。全部历史内置默认模板会迁移为墨灵，自写人设保留。
